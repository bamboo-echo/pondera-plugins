---

针对 `$1` 设计透视与公式方案，输出形态为 `$2`。**只给方案与公式，不改用户工作簿。**

**执行步骤**

1. **先约定口径**：明确行维度、列维度、值字段与聚合方式（求和/计数/去重计数/平均），并写清空值与负数的处理。
2. **整理源数据**：必须是「一行一记录」的扁平表，禁止合并单元格与多行表头；先检查主键唯一性。
3. **透视表布局**：行字段放低基数维度（区域、品类），列字段放高基数维度（月份、渠道），值字段只放数值列。
4. **公式方案**：按场景选 `SUMIFS`（多条件求和）、`COUNTIFS`（多条件计数）、`XLOOKUP`（精确/近似查找）、`FILTER`+`SORT`（动态数组）、`LET`（复用中间值）。
5. **校验列**：给每张汇总表加行数校验与金额校验，防止透视缓存未刷新。
6. **刷新机制**：说明 `Alt+F5` 刷新透视、打开时刷新、以及缓存泄漏导致旧数据的问题。

**可直接使用的公式**

```text
# 多条件求和：A=区域 B=品类 D=金额 G2=区域 H$1=品类
=SUMIFS($D:$D,$A:$A,$G2,$B:$B,H$1)

# 多条件计数
=COUNTIFS($A:$A,$G2,$C:$C,"已完成")

# 精确查找（找不到返回空而不是 #N/A）
=IFERROR(XLOOKUP($A2,Sheet2!$A:$A,Sheet2!$C:$C),"")
```

**判定规则**

- 透视缓存与源表行数不一致 → `高`，先刷新再出结论。
- 用 `VLOOKUP` 且查找列在返回值右侧 → 建议改 `XLOOKUP`，避免插列错位。
- 汇总金额与源表 `SUM` 差额 > 0.01 → 口径或重复计数问题，必须定位。
- 有合并单元格或多行表头 → 阻断，先规范化源数据。
- 用 `COUNT` 当作去重计数 → 明确改为 `COUNTIFS` 或透视「去重计数」。

**纪律**

- 不虚构单元格地址；按用户实际表结构给引用。
- 公式必须能直接粘贴运行，含绝对/相对引用说明。
- 不承诺公式性能；大数据量建议用 Power Query 或数据库。

**进阶场景**

| 场景 | 做法 | 注意 |
| --- | --- | --- |
| 数据超过 100 万行 | 载入数据模型，用 Power Pivot 度量值 | 不要落到工作表 |
| 按日期分组 | 透视「组合」日期（年/季/月） | 需先确认日期是真日期而非文本 |
| TopN 排名 | 值筛选前 N 项 + 辅助排名列 | 并列时用 `RANK.EQ` 明确规则 |
| 多表关联 | Power Query 合并查询 | 避免用 VLOOKUP 硬拼 |
| 动态数组溢出 | `FILTER` + `SORT` + `UNIQUE` | 确认目标区域留空，否则报 `#SPILL!` |
