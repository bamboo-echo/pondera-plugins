# 长文档分层摘要

## 何时使用

- 文档超出单次阅读范围（>2000 行或 >20 页），需要先建立地图再读细节。
- 用户只想要结论，但又要能回溯依据。
- 需要判断文档里的主张可信度。

不用于替代精读：涉及法律条款、安全规范时只做定位，不替用户下结论。

## 执行步骤

1. **建立结构地图**：按原文章节顺序列出标题与每节主题词，标出哪几节承载核心论点。
2. **逐节提炼**：每节输出 1–3 条要点，保留原文中的数字、单位、时间、适用范围；删除例子与修辞。
3. **区分层级**：
   - 事实（可验证的数据、定义、引用）
   - 观点/主张（作者的判断）
   - 建议（明确的操作要求）
   同一句里混有两者时拆开写。
4. **收敛全局**：用 3–5 句话回答「文档在解决什么问题、给出什么答案、边界在哪」。
5. **抽取关键引文**：每节最多 1 条原句，带章节位置，方便用户核查。
6. **标出矛盾与缺口**：前后不一致的数字、未定义术语、缺少来源的断言。

## 判定规则

- 摘要里出现的数字必须来自原文；换算过的要标注「按原文换算」。
- 原文没有结论时写「文档未给出明确结论」，不要替作者归纳出立场。
- 引文必须逐字，不改写、不拼接。
- 超过 3 层嵌套的限定条件（「在 X 情况下、若 Y、且 Z」）单独列为适用范围。
- 无法确认作者意图时写「意图不明」，不要脑补动机。

## 输出格式

```markdown
## 一句话结论
<...>

## 文档地图
| 章节 | 主题 | 是否核心 |

## 关键要点
1. <事实型要点，带数字/范围>
2. <主张型要点，标注「作者观点」>

## 关键引文
> <原句>　——<章节位置>

## 矛盾与缺口
- ...

## 适用边界
- 本文结论仅在 <条件> 下成立
```

## 纪律

- 摘要长度与原文长度成比例，长文不要压成三行。
- 不把「可能」「预计」改写成确定语气。
- 需要精读的章节要明确点名，别让用户误以为摘要已覆盖全部内容。
