---
description: 汇总一周工作产出，生成面向主管的周报
argument-hint: [起始日期或"上周"] [作者过滤，可选]
---

生成一份周报。

- 时间范围：`$1`（为空则取最近 7 个自然日）
- 作者过滤：`$2`（为空则当前 git 用户）
- 先执行只读命令收集事实，不要凭记忆编写：
  ```bash
  git log --no-merges --author="<作者>" --since="<起>" --pretty=format:'%h%x09%ad%x09%s' --date=short
  git diff --stat <起始 sha>..HEAD
  ```
  若仓库有 issue/PR 记录（`gh issue list --state all`），补上关闭与新建数量。

**整理规则**

1. 把提交按「目标」聚类，不按提交时间罗列。每个目标写：做了什么、为什么、当前状态（完成 / 进行中 / 被阻塞）。
2. 量化只使用可核实的数据：提交数、改动文件数、关闭 issue 数、新增测试数。没有数据就不写数字。
3. 阻塞项必须写清「卡在谁 / 卡在什么」，不能只写「有困难」。
4. 下周计划只列已确认的 3–5 项，每项带可验收的结果，不写「继续推进 X」。
5. 略去例行维护（依赖升级、格式化）中的非关键项，最多合并成一行。

**输出格式**

```markdown
## 周报（<起> ~ <止>）

### 本周目标与结果
1. **<目标>**：<结果>（<量化>）
   - 状态：完成 / 进行中 / 被阻塞

### 数据
- 提交 <n> 个，改动 <m> 个文件，关闭 issue <k> 个

### 阻塞与风险
- <阻塞项>：<卡点>，需要 <谁> 在 <时间> 前给结论

### 下周计划
| 事项 | 预期结果 | 依赖 |

### 需要上级决策
- <需要拍板的问题>
```

**纪律**

- 不编造数字、不夸大影响、不写「大幅提升」这类无依据形容词。
- 不把同一件事拆成多条充数。
- 输出后提醒用户核对阻塞项与下周计划。
