description: 检查设计 token 与样式的漂移，输出硬编码值与命名不一致清单
argument-hint: [token 定义文件] [样式/组件目录]
---

检查设计 token 是否被正确使用。

- token 源：`$1`（CSS 变量、SCSS map、Tailwind 配置或 tokens.json）
- 使用侧：`$2`（组件与样式目录）

**执行步骤**

1. 解析 token 源，建立三张表：颜色、间距/尺寸、字体（字号/行高/字重）。记录每个 token 的名字、值、层级。
2. 扫描使用侧，找出三类问题：
   - **硬编码**：出现 `#rrggbb`、`rgb()`、`hsl()`、`px`/`rem` 字面值但未引用 token 的地方。
   - **命名不一致**：同一语义出现多个名字（`--color-primary` 与 `--brand-blue`），或命名层级混乱（`--gray-1`/`--gray-light` 混用）。
   - **别名滥用**：语义 token 直接指向品牌色原始值（`--text-primary: #0a84ff`），换主题时无法跟随。
3. 对每个硬编码值做「最近 token」匹配，给出建议替换；差值明显（ΔE > 3 或间距差 ≥ 4px）时标注为「近似但不等价」。
4. 检查主题覆盖：暗色/高对比主题是否缺少对应 token，或覆盖后仍沿用浅色值。
5. 给出可执行修复：优先改引用，不新建 token；确实缺语义层时才建议新增。

**输出格式**

```markdown
## Token 一致性报告

**Token 源**：<...>（<n> 个颜色 / <m> 个间距 / <k> 个字体 token）
**扫描范围**：<...>

### 硬编码（需替换）
| # | 位置 | 当前值 | 建议 token | 是否等价 |

### 命名冲突
| 语义 | 现有名字 | 建议保留 | 说明 |

### 别名/层级问题
| token | 问题 | 影响（主题切换） |

### 主题覆盖缺口
| token | light | dark | 结论 |

### 修复顺序
1. ...
```

**纪律**

- 只读检查，不批量改写文件；先给清单让用户确认。
- 等价替换才标「可直接替换」，颜色差异要说明肉眼可见程度。
- 不新增设计规范，只对齐已有 token 体系。
