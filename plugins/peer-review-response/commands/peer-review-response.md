---
description: 根据审稿意见生成 point-by-point 回复信与修改清单
argument-hint: [审稿意见文本或文件] [稿件版本/修改说明，可选]
---

为下面的审稿意见撰写逐条回复信。审稿意见来自 `$1`，修改信息来自 `$2`（为空则只写回复框架，不虚构改动）。

**执行步骤**

1. 拆分意见：给每条编号（R1-1、R2-1…），区分「事实性质疑 / 方法质疑 / 表述问题 / 补充实验要求 / 格式问题」。
2. 对每条判定处理方式，只允许四种：
   - **已修改**：写明改在哪一节、改前改后差异、页码/行号。
   - **部分修改**：说明接受哪部分、为何不接受另一部分。
   - **礼貌反驳**：给出证据（文献、实验、定义），不评价审稿人。
   - **无法完成**：说明客观限制（数据不可得、设备限制），并给出替代方案。
3. 合并重复意见：同一问题被多位审稿人提到时，回复一次并在开头注明「R1-2 与 R2-3 同一问题」。
4. 检查一致性：回复里声称的修改必须在稿件中真实存在；不可用「我们相信」「显然」作为论据。
5. 生成回复信开头段：感谢、概述主要改动、说明新增实验（如有）。
6. 生成修改清单：按章节顺序列出改动，便于编辑核对。

**输出格式**

```markdown
## Response to Reviewers

Dear Editor and Reviewers,
<感谢 + 3 句概述主要改动>

### Reviewer 1

**R1-1**：<意见摘要>
**Response**：<接受/部分接受/反驳/无法完成>。<证据与理由>
**Change**：<章节、页码、行号；无改动则写 None>

**R1-2**：...
（同一问题合并时：**R1-2 / R2-3**：...）

### Reviewer 2
...

## Summary of Changes
| # | 位置 | 改动 | 对应意见 |
```

**纪律**

- 不虚构实验数据、页码、行号；不知道就留 `<待填>`。
- 反驳必须给证据，不得使用情绪化措辞。
- 不承诺「未来会做」作为对必改意见的回应。
- 保持每条意见独立可核对，不把多条揉成一段。
