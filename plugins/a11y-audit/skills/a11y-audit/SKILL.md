# 可访问性审计（WCAG 2.2）

## 何时使用

- 新页面 / 新组件上线前做 a11y 检查。
- 用户反馈「键盘 Tab 不了」「读屏读不出来」「颜色看不清」。
- 需要判断某个 ARIA 写法是否合规。

不负责视觉设计改版，只给可验证的问题与最小修复。

## 执行步骤

1. **静态结构检查**：读组件与样式，确认语义标签、标题层级、landmark、图片替代文本。
2. **键盘走查清单**：逐个交互元素确认可达、可操作、有可见焦点。
3. **焦点管理**：弹窗打开/关闭后的焦点落点、路由切换后的焦点、`aria-live` 播报。
4. **对比度计算**：对文本/背景组合计算对比度，正文要求 ≥4.5:1，大字 ≥3:1，非文本 UI 边界 ≥3:1。
5. **表单与错误**：label 关联、必填说明、错误文本与字段的关联、错误出现时的播报。
6. **动态与动画**：`prefers-reduced-motion`、自动播放、轮播暂停、闪烁频率。
7. **给出验证方式**：键盘实测、读屏（NVDA / VoiceOver / TalkBack）、浏览器内建 a11y 树检查；标注哪些结论必须人工实测。

## 检查清单

- `<div onClick>` 无 `role` / `tabIndex` / 键盘处理 → 不可达。
- 可点击元素缺少 `cursor` 与焦点样式，`outline: none` 且未提供替代 → 阻断。
- 图标按钮没有 `aria-label`，或 label 只有「点击这里」→ 不可理解。
- 标题跳级（h2 → h4）、一个页面多个 h1 → 结构问题。
- 图片 `alt` 为空仅适用于装饰图；信息图必须描述内容。
- `aria-hidden` 用在仍可聚焦的元素上 → 不一致。
- 弹窗缺少 `role="dialog"`、`aria-modal`、初始焦点与焦点陷阱。
- 打开弹窗后背景可 Tab → 焦点逃逸。
- `aria-live` 未设置或设置为 `assertive` 用于非紧急信息 → 播报噪音。
- 表单错误只用颜色或图标表达，没有文本 → 违反 1.4.1。
- 禁用按钮对比度过低且无文本说明原因。
- 链接文本「了解更多」重复出现，脱离上下文不可辨。
- 只有 hover 才显示的信息，键盘用户拿不到。
- 动画未响应 `prefers-reduced-motion`。
- 目标尺寸小于 24×24 px（WCAG 2.2 AA 目标尺寸）。
- 拖拽交互没有单点替代方案（2.5.7）。
- 粘贴/复制的验证码式交互（3.3.8）无替代。

## 判定规则

- 完全阻断键盘用户完成核心任务 → 严重（A 级）。
- 信息无法被读屏获取，但视觉可用 → 严重（A 级）。
- 对比度不达标、目标尺寸过小 → 中等（AA 级）。
- 最佳实践缺失（landmark 冗余、heading 顺序）→ 建议。
- 无法静态确认的（真实读屏播报、焦点顺序）→ 标「需人工实测」，不计入结论计数。

## 输出格式

```markdown
## 可访问性审计：<页面/组件>

**检查范围**：<文件清单>
**已验证**：<静态检查项> / **需人工**：<键盘、读屏项>

### 严重（阻断核心任务，WCAG A）
| # | 位置 | 问题 | 影响用户 | 修复 |

### 中等（AA）
| # | 位置 | 问题 | 实测值 | 达标值 | 修复 |

### 建议
- ...

### 需人工验证
- [ ] 键盘 Tab 顺序：<路径>
- [ ] 读屏播报：<组件>
```

## 纪律

- 对比度必须给出计算值，不要凭肉眼判断。
- 不为了「看起来合规」建议堆 ARIA；优先用原生语义元素。
- 未实测的读屏行为不得写成确定结论。
