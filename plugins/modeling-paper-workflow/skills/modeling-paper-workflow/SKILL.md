# 数学建模论文写作流程

## 何时使用

- 赛题到手，需要判断题型并确定整体解题—写作路线。
- 模型已跑通，但论文结构混乱、摘要写不出来。
- 需要自查论文是否存在常见扣分项。

选型本身用 `model-selection-matrix`；灵敏度细节用 `sensitivity-analysis-checklist`。

## 执行步骤

1. **审题拆问**：把题目拆成「背景数据、明确要求、隐含约束、交付物」四栏；逐问标出输入、输出、评价指标。任何一问都不能改写题意。
2. **建假设**：每条假设写「假设内容 + 真实世界对应 + 对模型的影响」。只保留后文真正用到的假设，数量控制在 4–8 条。
3. **列符号表**：符号、含义、单位、取值范围；同一符号全文唯一，避免 `x` 既是变量又是向量。
4. **建模型**：先给目标函数/约束/状态转移的数学表达，再解释为什么这样建模；复杂模型拆成「主模型 + 子模块」。
5. **求解**：写清算法步骤、参数取值、收敛判据、工具与版本；给出伪代码或流程图，不只写「用遗传算法求解」。
6. **检验**：误差指标、残差分析、交叉验证、与实际数据比对；至少一种独立检验方式。
7. **灵敏度**：选 1–3 个关键参数扰动 ±10%/±20%，给出结果变化表与稳定性结论。
8. **评价与推广**：优点（3 条，需有依据）、缺点（必须真实）、改进方向（可执行）。
9. **写摘要**（最后写）：问题一句、方法一句、每问结果带数字、结论一句；摘要里不得出现未在正文出现的数字。

## 常见失分点

- 摘要没有具体结果数字，只有「本文建立了模型并求解」。
- 假设与模型脱节：假设了线性，却用非线性模型且不解释。
- 符号表缺失，正文首次出现的变量没有定义。
- 只报最优解，不给求解过程与参数设置，无法复现。
- 灵敏度分析只写「结果稳定」，没有扰动表。
- 图表无标题、无单位、无坐标轴说明，或图表与正文结论不对应。
- 问题重述照抄原题（部分赛制按抄袭处理）。
- 模型评价只写优点，缺点写成「计算量较大」这类套话。

## 判定规则

- 某问没有独立结果 → 摘要中不得声称已解决该问。
- 参数数量超过数据量级 → 提示过拟合风险，要求降维或正则化。
- 检验方式与模型假设冲突（如假设独立却用时间序列交叉验证）→ 必须替换。
- 灵敏度扰动后结论反转 → 结论降级为「条件成立」并写明条件。

## 输出格式

```markdown
## 建模论文工作台

**题型**：<优化 / 预测 / 评价 / 机理 / 统计>
**各问输入输出**：<表>

### 假设（每条含影响）
1. <假设>｜现实对应：<...>｜影响：<...>

### 符号表
| 符号 | 含义 | 单位 | 范围 |

### 逐问模型
- 问题一：目标/约束/算法/结果
- 问题二：...

### 检验与灵敏度计划
| 项 | 方法 | 参数 | 预期输出 |

### 摘要草案
<问题—方法—结果（数字）—结论>
```

## 纪律

- 不替用户编造数据与结果数字。
- 不把未验证的模型写成「已验证有效」。
- 摘要与正文必须一致；发现不一致时先改正文或改摘要，不允许两边各说一套。
