# 长文分句翻译流程

## 何时使用

- 文档超过 3000 字，整篇一次性翻译会出现术语漂移、指代错乱。
- 多人协作翻译，需要统一术语与分段边界。
- 译文要保留原文结构（标题层级、列表、代码块、表格）。

## 流程

### 1. 结构提取

先保留骨架再动字：标题、列表项、表格单元格、代码块、引用块各自成段。代码块与命令行**不翻译**，只标注。

### 2. 切分规则

- 一个语义段 = 一个完整论点或一个操作步骤，通常 1–3 句。
- 不切断：主谓宾、定语从句、`not only ... but also` 类关联结构、跨句指代（"this approach" 必须与其先行词同段）。
- 可以切断：并列句、转折后的新论点、列表项之间。
- 每段带稳定 ID：`s001`、`s002`，便于回填与审校。

### 3. 术语锚定

翻译前先扫全文产出术语候选表，确定每个概念的唯一译法。术语一旦定稿，后续段落不得换词。

| 原文术语 | 译文 | 词性 | 禁用变体 | 依据 |
| --- | --- | --- | --- | --- |

出现同义不同译（如 `throughput` 既译「吞吐量」又译「通过率」）必须回改统一。

### 4. 逐段翻译

按 ID 顺序翻译，每段输入包含：上文最后一段的译文（供指代衔接）、本段原文、术语表。输出只给本段译文，不擅自扩写。

### 5. 回译校验

抽样 15%–20% 段落做回译（译文→原文语言），比对三点：事实是否一致、数字与单位是否一致、逻辑连接词是否保留。偏差段落重译。

### 6. 拼装

按原始骨架回填，检查：标题层级未变、列表项数量一致、表格行列一致、代码块原样、脚注编号连续。

## 一致性检查清单

- [ ] 同一术语全文唯一译法
- [ ] 人称与语气统一（敬语/中性/first person）
- [ ] 数字格式与单位随目标语言规范
- [ ] 缩写首次出现给全称
- [ ] 交叉引用（"见第 3 节"）编号未错位
- [ ] 图表标题与正文引用一致
- [ ] 段落数与原文对齐，无漏译/重译

## 输出格式

```markdown
## 翻译分段表：<文档名>

**统计**：原文 N 段 / 已译 N 段 / 回译抽样 N 段

| ID | 原文摘要 | 译文 | 术语命中 | 回译偏差 |
| --- | --- | --- | --- | --- |

### 术语表
### 未解决问题
- <歧义、需作者确认的表述>
```

## 判定规则

- 段落内出现新术语 → 先回填术语表，再继续，不允许「先译后统一」。
- 回译出现事实性偏差（数字、否定、条件）→ 该段必须重译，不接受润色。
- 指代无法在同段内闭合 → 拆段位置错误，需要合并前后段。
- 译文长度超出原文 1.6 倍 → 标为「可能过度解释」，逐句核对是否加了原文没有的信息。

## 纪律

- 不合并段落，不为了通顺删减原文信息。
- 不翻译代码、命令、文件路径、API 名称。
- 术语表变更必须记录变更点，便于回改已译段落。
